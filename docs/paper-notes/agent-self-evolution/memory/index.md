# 记忆演化

> 本目录讨论 Agent 如何将交互轨迹转换为可继承状态。这里的“记忆”既包括外部文本/检索记忆，也包括 episode 内的快速参数记忆。重点不在于记忆存储容量，而在于记忆是否被正确提炼、选择、使用、修订与评估。

## 研究问题

记忆演化通常围绕以下链路展开：

```mermaid
flowchart LR
    A[任务执行轨迹] --> B[经验提取]
    B --> C[记忆候选]
    C --> D[写入 / 更新 / 遗忘策略]
    D --> E[长期记忆或 Fast Weights]
    E --> F[检索 / 参数适应]
    F --> G[后续任务执行]
    G --> H[验证器或奖励]
    H --> B
```

核心难点包括：

- 轨迹中哪些内容是可迁移经验，哪些只是单例噪声；
- 成功、失败与环境反馈应如何影响记忆更新；
- 记忆是否真正改变了后续动作，而非仅增加上下文长度；
- 错误记忆如何被发现、修订、遗忘或回滚；
- 外部记忆、参数记忆和记忆策略学习分别适合什么场景。

## 阅读顺序

建议先把四种“记忆写入位置”区分开：

```text
MemRL：把记忆条目的使用策略变成可学习的 Q 值
MemSkill：把记忆提取、更新和删除写成可演化 Skill
UMEM：联合优化记忆提取与 Memory Bank 管理
TMEM：把经验进一步写入 episode 内的 LoRA Fast Weights
```

EvoMemBench 放在最后阅读，用它检查前面方法到底测到了哪一种记忆能力。

## 方法比较

| 方法 | 更新位置 | 是否更新基础模型权重 | 主要反馈 | 主要风险 |
| --- | --- | ---: | --- | --- |
| UMEM | Memory 内容与管理策略 | 取决于 Mem-Optimizer 训练设定 | 语义邻域边际效用 | 邻域建模偏差、长期噪声 |
| TMEM | LoRA Fast Weights | 仅 episode 内快速参数 | 经验提炼与 RL | 在线适应成本、参数漂移 |
| MemRL | Episodic Memory 策略 | 否 | 运行时 RL reward | credit assignment 与污染 |
| MemSkill | 记忆操作 Skill | 通常否 | 硬案例与任务结果 | Skill 控制器错误 |
| EvoMemBench | 评测层 | 否 | 基准 oracle | 覆盖范围与任务偏差 |

## 阅读原则

对于每篇记忆演化论文，建议按以下问题审查：

```text
记忆条目是什么形式？
写入动作如何定义？
什么反馈决定保留或删除？
记忆在后续行为中如何被调用？
是否测试未见任务与跨 episode 泛化？
是否报告错误记忆、遗忘和回滚？
```

每篇文章均按照“研究问题 - 方法 - 实验协议 - 原文图表 - 结果解释 - 消融与边界 - 高频问题”的顺序展开。数值只在论文原文明确报告时保留；无法由实验直接推出的结论会单独标注。
